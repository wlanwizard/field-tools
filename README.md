# field-tools

Quick, one-shot Python, shell and PowerShell scripts for sysadmin and network
engineering work. Built to be pulled onto a **customer-owned laptop**, run, and
removed, with no installs and nothing left behind except the results you choose to keep.

---

## Get it onto the machine

Pick whichever works on the box in front of you. **No git needed** for the zip options.

**macOS / Linux**
```bash
curl -L https://github.com/wlanwizard/field-tools/archive/refs/heads/main.tar.gz | tar xz
cd field-tools-main
```

**Windows (PowerShell 5.1+)**
```powershell
iwr https://github.com/wlanwizard/field-tools/archive/refs/heads/main.zip -OutFile ft.zip
Expand-Archive ft.zip -DestinationPath . ; cd .\field-tools-main
Get-ChildItem -Recurse | Unblock-File      # clears "downloaded from internet" flag
```

**git available**
```bash
git clone --depth 1 https://github.com/wlanwizard/field-tools.git
```

**Private repo?** The links above only work while the repo is public. For a
private repo, use a read-only deploy key made on the laptop. See
[docs/REPO-SETUP.md](docs/REPO-SETUP.md).

## Run a tool

Every tool is in `tools/`, and its number is the quick way to find it:

```bash
cd tools
ls 002*                                   # find tool 002 in any language
python3 002-port-check.lmw.py --help          # Windows: py instead of python3
bash 003-host-snapshot.lm.sh -h
```
```powershell
cd tools
powershell -ExecutionPolicy Bypass -File .\002-port-check.w.ps1 -?
```

`-ExecutionPolicy Bypass` applies to that one process only; it doesn't change the
customer's policy.

Every tool prints to the screen. Add `--out` / `-o` / `-Out` to also save a file to
`./output/` named `<NNN>_<hostname>_<timestamp>.<ext>`.

## Cleaning up

Copy anything you need out of `output/`, then delete the whole folder (and the
zip). Nothing is installed, so nothing else needs removing.

## Naming convention

```
tools/<NNN>-<verb-noun>.<platforms>.<ext>
      001-wlc-telemetry-compare.lmw.py
      002-port-check.lmw.py
      002-port-check.w.ps1      <- same tool, same number, another language
      003-host-snapshot.lm.sh
```

- **NNN**: 3 digits, one sequence for the whole repo, **never reused or renumbered**.
  The number is how you refer to a tool and how you find it (`ls 002*`, "run 002").
- **verb-noun**: lowercase and hyphenated, says what it does: `port-check`,
  `dhcp-scope-export`, `ad-stale-users`.
- **platforms**: where that file runs: `l` Linux, `m` macOS, `w` Windows, always
  in that order (`lmw`, `lm`, `w`, ...). On a Windows laptop, `ls *w.*` lists
  what will run there.
- **ext**: the language: `.py` Python, `.sh` bash, `.ps1` PowerShell. One number can
  have several language versions.
- **Category** is a line in the tool's header, not a folder. It only decides which
  section of the catalog below the tool appears in:

| Category | For |
|----------|-----|
| `net` | Reachability, DNS, DHCP, Wi-Fi, switching/routing, captures |
| `sys` | OS inventory, services, disks, logs, patches |
| `ident` | Active Directory, Entra ID, LDAP, certificates |
| `sec` | Audits, TLS/cert checks, open shares, local admin review |
| `cloud` | Azure, AWS, M365, SaaS APIs |
| `util` | Helpers that fit nowhere else (file hashing, CSV merge, etc.) |

## Adding or changing a tool

Tools are written with Claude Code, which follows the conventions in
[`CLAUDE.md`](CLAUDE.md). Open Claude Code in this repo and ask for what you need,
or use the `/new-tool` command:

```
/new-tool check DHCP scopes on a Windows server for utilization over 80%
```

Claude picks the next free number and a category, starts from the matching file in
`templates/`, tests what it can locally, and refreshes the catalog with
`python3 catalog.py`. Retired tools move to `_retired/` and their number is never reused.

Rules every tool follows (customer machine, so be a polite guest):

1. **No installs.** Python is stdlib only. PowerShell uses built-in cmdlets
   (Windows PowerShell 5.1). Shell sticks to what ships with macOS and Linux (bash 3.2).
2. **Read-only by default.** Anything that changes state needs an explicit flag
   (`--apply`, `-Fix`) and says what it will do first.
3. **No secrets in the repo.** Credentials are prompted for or passed at runtime,
   never hard-coded. No customer names, IPs, or output gets committed (`output/`
   is git-ignored).
4. **No phoning home.** A tool only talks to the targets you give it.
5. **Self-documenting.** `--help` / `-h` / `Get-Help` works, and the header has
   `Synopsis:`, `Category:`, `Requires:`.
